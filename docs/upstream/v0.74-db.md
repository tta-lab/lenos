## Core reliability fixes (MERGE ALL)

### `61ee2d2e` — fix(db): use connection pool to avoid corrupted writes
✅ **MERGED** (PR #119)

Replace Go's default unlimited connection pool with `SetMaxOpenConns(1)`.
SQLite serializes writes at the file level — extra pool connections
added race surface, not throughput. All callers queue through one handle.

**Files changed:** `internal/db/db.go`
**Check:** We also use `database/sql` — find the Open call and add
`SetMaxOpenConns(1)` after migration setup. Also check `_txlock=immediate`.

### `40108413` — fix(db): prevent SQLITE_NOTADB corruption under concurrent sub-agents
✅ **MERGED** (PR #119)

Two changes:
1. `db.SetMaxOpenConns(1)` — concurrent sub-agents serialize through one
   SQLite handle, eliminating cross-handle WAL/checkpoint races.
2. Add `_txlock=immediate` to DSN — `BEGIN IMMEDIATE` acquires
   reserved-writer lock upfront. Concurrent writers queue cleanly on
   `busy_timeout` instead of racing deferred-to-writer upgrade.

For the ncruces driver the DSN must use `file:` URI prefix for query
params to be parsed; the plain path form silently ignores `_txlock`.

**Files changed:** `internal/db/db.go` (Open call DSN)
**Check:** What SQLite driver are we using? (`modernc.org/sqlite` or
`ncruces/go-sqlite3`) — affects DSN format for `_txlock`.
