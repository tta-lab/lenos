## MERGED commits

### `c2be8cbf` — fix: set non-interactive env vars in shell to prevent editor hangs

Sets `TERM=xterm-256color`, `EDITOR=false`, `VISUAL=false`, `PAGER=cat`,
`GIT_PAGER=cat`, `JJ_EDITOR=false`, `JJ_PAGER=cat` in `mergeEnv` so
commands won't spawn editors/pagers on a nonexistent TTY.

**Files:** `internal/agent/exec.go` — `mergeEnv` function
**Audit:** Diff verified from upstream. Upstream adds env vars in
`internal/shell/run.go` via `shell.go`. Our port does the same in
`internal/agent/exec.go:mergeEnv` — the function that constructs
the subprocess environment. Same set of vars: TERM, EDITOR, VISUAL,
PAGER, GIT_PAGER, JJ_EDITOR, JJ_PAGER. Upstream also adds
GIT_EDITOR; we omit it since EDITOR=false covers the same case.

### `9d346688` — fix(agent): release activeRequests before publishing TypeAgentFinished

Bug: TUI stays stuck on spinner after turn finishes because `IsSessionBusy()`
polls activeRequests which hasn't been released yet. Reorder so cleanup runs
before notification.

**Files:** `internal/agent/agent_run.go` — `Run` method
**Audit:** Diff verified from upstream. Same pattern — upstream
`internal/agent/agent.go:581` has the identical issue: notification
fires before `activeRequests` cleanup. Our fix adds explicit
`cancel()` + `activeRequests.Del()` before both the error-finish
branch and the TypeAgentFinished notification.

### `a4020df6` — fix(summarize): reauthenticate oauth tokens when used to summarize

OAuth token may expire between regular turns; summarize needs its own reauth path.

**Files:** `internal/agent/coordinator.go` — `Summarize` method
**Audit:** Diff verified from upstream. Upstream adds inline OAuth
refresh + 401 retry in `coordinator.go:961`. Our port adds
`maybeRefreshToken()` call before summarizing (shared helper,
see `8cd4786c`). We don't implement the 401 retry loop in
Summarize since our `isauthorized` check already lives in `Run`
and the summarize stream failure manifests as a stream error,
not a 401.

### `8cd4786c` — refactor(coordinator): extract token refresh helpers

Extract `maybeRefreshToken` from both `Run` and `Summarize` to reduce duplication.

**Files:** `internal/agent/coordinator.go` — new `maybeRefreshToken` method,
`Run` and `Summarize` callers
**Audit:** Diff verified from upstream. Upstream extracts two helpers
(`refreshTokenIfExpired`, `retryAfterUnauthorized`) for dedup across
`Run` and `Summarize`. Our port creates `maybeRefreshToken` — a single
helper covering the proactive refresh path. The 401 retry path already
lives in `Run` and doesn't apply to `Summarize` in our codebase since
summarize is a stream call, not a top-level run.

### `61f49b23` — fix(agent): drain queued messages after manual session summarize

Manual summarize leaves queued messages unprocessed. Drain them after summarize
completes successfully.

**Files:** `internal/agent/agent_session.go` — `Summarize` method
**Audit:** Diff verified from upstream. Upstream fix lives in
`internal/agent/agent.go:732` (sessionAgent.Summarize). Our port
placed it in the same location (`agent_session.go:107`). Upstream
uses `messageQueue.Get` + `Set` to drain; we use `Take` + `Set`
which is equivalent.

### `2faa467a` — fix: fix sometimes sending reasoning effort when it shouldn't

Sometimes `ModelCfg.ReasoningEffort` (e.g. "high") is set on a model that
doesn't support reasoning effort levels. Check `CatwalkCfg.CanReason` before
sending.

**Files:** `internal/agent/coordinator.go` — `getProviderOptions` function
**Audit:** Diff verified from upstream. Upstream defines
`shouldSetEffort := model.CatwalkCfg.CanReason &&
slices.Contains(...)` and applies it to openai/azure, anthropic, and
openrouter branches. Our port matches this exactly — same boolean
guard, same branches.
