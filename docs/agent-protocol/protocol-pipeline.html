Lenos Protocol

Lenos has one top-level agent output protocol: bash. Human prose, routing, recovery, storage, and TUI rendering all sit behind that single shape instead of adding a second in-band markdown mode.

Top-level emit Raw shell text, or bare exit.
Human prose narrate heredoc events, not :md.
State owner SQLite message rows remain the persistent source of truth.

Design Rule

If a behavior cannot be expressed as bash plus runtime-owned result metadata, it does not belong in the agent emit format.

Protocol Contract

The model does not call JSON tools and does not switch into markdown. Every assistant response is shell input. Communication uses shell too: the runtime injects a narrate function before execution.

Execution

Normal work is plain bash. Comments are allowed because bash ignores them and the transcript keeps them.

# inspect the protocol package
rg -n "narrate|classify" internal/agent

Prose

Reader-facing markdown is stdin to narrate. Positional message arguments are rejected.

cat <<'EOF' | narrate
Done. Tests pass.
EOF

Control

Use --continue for progress notes that should not end the loop. Bare exit ends without bash execution.

cat <<'EOF' | narrate --continue
I found the parser and will patch it next.
EOF

Processing Pipeline

The runtime turns one model emission into either a corrective observation, one bash subprocess, or a loop stop.

Parsers and Rules

Lenos deliberately avoids a full shell parser. It combines small structural gates, bash's own syntax checker, and a few targeted recovery rules.

Gate Parser or Rule Runtime Action
empty emit strings.TrimSpace is empty. Persist a runtime re-prompt asking for bash, comment, narrate, or exit.
bare exit ^\s*exit(\s+-?\d+)?\s*$. Multi-line exit and cmd && exit do not match. Finish the assistant row and stop the loop without bash execution.
banned edits Regexes for sed -i, sed --in-place, and perl -i after command separators. Block before bash -n and re-prompt toward safer edit tools.
tool-call wrappers Regexes for XML and bracket-shaped tool/function call hallucinations. Delete the bad assistant row and send a high-salience protocol correction.
salvage First line is natural language; remaining lines are valid, strongly bash-shaped, and command/path probes pass. Rewrite first line into # comment, then execute the rest as bash.
natural language First non-whitespace byte is not lowercase ASCII and not #; uppercase first lines containing = are spared; ## headings are prose. Rewrite whole emit into a random-delimited narrate heredoc and execute it.
bash syntax /bin/bash -n reads the emit on stdin. Invalid syntax gets a runtime correction. Host-level checker failures are logged and treated as valid.
command not found After execution, stderr is scanned for the first missing command. Prepend a high-salience alert before the result envelope and continue the loop.
timeout Runner returns context.DeadlineExceeded. Store exit code 124 and re-prompt with guidance to use bash-native timeout.

Rewrite Paths

Rewrites are intentionally narrow. They repair common model mistakes without creating a second protocol mode.

Salvage: prose header plus bash

The first line becomes a comment only if the rest is valid and has command evidence.

I will inspect the repo.
rg -n "narrate" internal/agent && go test ./internal/agent

# rewritten to:
# I will inspect the repo.
rg -n "narrate" internal/agent && go test ./internal/agent

Natural language to narrate

High-confidence prose is treated as reader-facing markdown. CJK and ## headings are covered.

实现已经完成，测试通过。

# rewritten to:
cat <<'LENOS_NARRATE_EOF_8HEX' | narrate
实现已经完成，测试通过。
LENOS_NARRATE_EOF_8HEX
Important: strings like :md, :continue, and :exit no longer have protocol meaning. They are just bytes inside the bash-only classification flow.

Narrate IPC

narrate is a shell function injected by Lenos. It is not a standalone protocol marker and it does not interrupt the surrounding bash.

Function Contract stdin only

  • narrate "Done" fails; body must come from stdin.
  • Empty body fails and removes the temporary event directory.
  • Multiple calls are allowed and sorted by event directory prefix.

Options composable

  • --to agent writes an addressee for parent-side delivery.
  • --continue writes a marker that prevents successful narration from ending the loop.
  • Options can appear in either order before stdin redirection.

Event Shape raw files

$LENOS_NARRATE_DIR/
  000001.xxxxxx/
    body
    to
    continue
  000002.xxxxxx/
    body

Delivery parent-owned

The child process writes addressed prose with narrate --to. Parent code handles delivery and stores delivery output on CommandNarration.

cat <<'EOF' | narrate --to reviewer
message
EOF

Loop Outcomes

Narration is visible to the human even when bash fails, but failure paths continue the agent loop so the model can recover.

Condition Human View Next Model Input Loop
exit 0, no narration Successful result row is hidden. Result envelope with stdout/stderr summary. Continue.
exit 0, narration Narration body renders as assistant-style markdown. No narration body replay. Stop unless any narration has --continue.
exit 0, --continue Narration renders normally. Status says continue requested; body omitted. Continue.
non-zero bash Failed command result first, narration after it. Failure observation plus narration status; body omitted. Continue.
delivery failure Local narration plus delivery failure row. Delivery failure details; body omitted. Continue.
bare exit No bash result. No result observation. Stop.

Storage and Rendering

The model sees what it emitted as assistant text. Runtime result metadata can render to humans without duplicating private body text in result replay.

Persisted Result Shape

type CommandNarration struct {
    Body string
    To string
    Continue bool
    DeliveryExitCode *int
    DeliveryOutput string
}

type CommandContent struct {
    Command string
    Output string
    ExitCode *int
    Pending bool
    Observation string
    Narrations []CommandNarration
}

TUI Extraction

  • Assistant rows render as bash previews with a $ prefix.
  • Exit 0 command results with no narration are skipped.
  • Failed results render command output and an exit badge.
  • Narration bodies render in separate assistant-style markdown items.
  • Delivery failures render as result rows without including the body.
Token rule: assistant history keeps the full emitted bash, including narrate heredoc bodies. FormatResults() omits CommandNarration.Body and only reports status such as narration rendered to user; body omitted from result replay.
