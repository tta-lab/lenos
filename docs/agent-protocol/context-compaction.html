Context Compaction

这页记录当前自动 compact 的真实行为、它和 bash-first protocol 的冲突、 以及下一步设计。目标不是引入第二种语言，而是让 compact 成为协议边界上的 一个清楚阶段。

Design stance

Compact 是每次模型采样前的门禁，不是“打断当前 assistant emit”的异常分支。 已经拿到的 emit 必须先走完 bash-first 生命周期。

现状

Lenos 的 compact 机制已经保留 SummaryMessageID 作为恢复边界。 本轮设计把触发点从旧的 post-stream 分支移到 pre-step 门禁。

threshold

阈值按剩余上下文算

shouldAutoCompact 对大窗口保留固定 20k token buffer， 小窗口保留 20%。触发依据来自 session 上一次保存的 PromptTokens + CompletionTokens。

trigger

旧触发点在 stream 之后

旧实现里 runLoop 先创建 assistant row，流式写入模型 emit， 然后调用 onUsage。如果此时达到阈值，loop 直接返回 stopShouldSummarize。

summary

Summary 会替换可见历史

Summarize 生成一条 IsSummaryMessage assistant message，并把 session 的 SummaryMessageID 指到它。恢复时从这条 summary 开始，并额外保留最近 3 条真实用户消息。

问题

真正的问题不是“summary 是否长得像 bash”，而是 auto compact 现在可以抢在 bash-first 生命周期之前发生。

current order

旧 step 顺序

1 stream 模型输出 assistant emit，增量写入 SQLite。
2 usage 保存 token usage，并立刻检查 compact 阈值。
3 compact 达到阈值就 summarize，再 re-enter runLoop。
4 classify 只有没 compact 才会分类、执行 bash、处理 narrate 或 exit。
protocol break

当前 emit 可能被丢在半路

emit 是 exit 时不会结束 turn；emit 是有效 bash 时不会执行； emit 是 narrate 时用户不会看到结果。测试里甚至固定了 “exit + compact 阈值 = compact 优先”的行为。

late rescue

只靠 post-stream usage 不够

如果下一次请求在发送前已经超窗，旧设计救不了。需要 pre-turn compact， 在新用户输入和上下文增量进入 prompt 之前先降历史。

Summary 形态

Q1 的结论应更精确：如果 summary 输出 narrate，这不是坏事。 对 Lenos 来说，这反而符合“只有一种 agent 输出语言”的方向。

accept

推荐：summary 是单个 narrate handoff

Compact summary 可以是合法 bash，但应限制为单个 narrate heredoc，不允许前后带其他命令。这样它既是 bash-first 世界里的 artifact， 又不会表达“还要执行某个动作”的副作用。

Summary 的语义是“给恢复模型看的 handoff”，不是“下一步要执行的 shell”。 用 narrate 可以保留单语言原则，但需要明确它是 compact 产物。v1 依赖 prompt 约束，不由 runtime 包装 summary body。 

# lenos context compaction: handoff from prior history
cat <<'LENOS_CONTEXT_COMPACTION' | narrate
## Current State
- User asked to inspect context pressure and compact behavior.
- We found auto compact can fire before classify/exec.

## Next Steps
1. Move compact check to the continuation boundary.
2. Add pre-turn compact before new user input can exceed the window.
LENOS_CONTEXT_COMPACTION

Codex 可借鉴点

Codex CLI 的 remote compact 服务端细节看不到，但本地触发、历史替换和 mid-turn 边界能看到。它的 inline compact prompt 也在本地，是一个短的 checkpoint handoff prompt。

pre-turn

采样前先 compact

Codex 在 turn 开始先检查历史 token，如果已经超过 auto compact limit， 先 compact 再进入正常采样。这能处理“下一次请求还没发就已经太大”的情况。

mid-turn

只在需要 follow-up 时 mid-turn compact

Codex 在一次 sampling 完成并处理输出后，只有还需要继续请求模型时才 compact。最终 assistant message 已经结束 turn 时，不再为了 compact 打断它。

history

替换历史是显式安装动作

Codex 的 compact 不是只写一个 summary 字段；它安装 replacement_history，通常包含保留的近期用户消息和 summary， 并把这个动作持久化为 compaction item。

prompt comparison

Codex prompt 更短，目标更窄

Codex 的 prompt 直接说这是 context checkpoint compaction，要求为接手的 LLM 写 handoff summary：进度、关键决定、约束、用户偏好、剩余步骤和继续 所需资料。它还用一个 summary prefix 告诉下一轮模型：这是另一个模型留下的 summary，要接着做，不要重复劳动。

Lenos prompt 仍然更像“完整会话总结清单”，要求很多分区和细节。好处是 不容易漏信息，坏处是偏长。当前实现已把 compact 指令放在最后一条 user message，并明确要求 summary 本身是 bash-first 世界里的单个 narrate emit。

learning

可学的是压缩目标，不是格式

Lenos 应保留自己的输出语言约束：compact summary 必须 emit 单个 narrate heredoc，不能输出 heredoc 外命令。可以学习 Codex 的 简洁度：少写模板化栏目，多强调“handoff 给下一个模型继续做事”。

还应学习它的 replay 语义：summary 不是孤立字段，而是替换历史的一部分。 除 summary 外，最好保留最近真实用户消息，让最新需求和纠正不只依赖模型总结。

下一步设计

设计目标：只做 pre-step compact。这里的 step 指一次模型采样和它对应的 bash-first 处理；pre-step 指下一次采样开始前，不是当前 emit 被处理前。

boundary

把 compact check 移到采样前

用户 turn 的第一步，是 Run 收到新 prompt 后触发的第一次模型 采样。它不是“会话第一条用户消息”。这一步前可以先检查旧历史是否已到阈值， 必要时 compact，再把当前用户请求送进采样。

continuation

result 后的下一步也走同一门禁

bash result、runtime re-prompt、queued user prompts 持久化后，如果 loop 还需要下一次模型采样，就在采样前检查 compact。若上一步已经通过 exit 或 non-continue narrate 结束 turn，就没有 下一步，也就不触发 compact。

summary spec

Summary 输出约束为 handoff bash

Summary prompt 明确要求输出一个 narrate heredoc，正文是结构化 handoff。禁止在 heredoc 外输出命令。runtime 不用 protocol.NarrateSection 包 summary body；v1 先依赖模型遵循 指令，不做复杂校验。

state

保留 summary message，但提高语义清晰度

短期可以继续用 SummaryMessageID 和 IsSummaryMessage。后续可加 dedicated compaction record， 记录 trigger、phase、replacement boundary 和 token before/after。

manual

手动入口叫 Compact Session

自动 compact 继续按阈值触发；用户也需要主动入口。命令面板里提供 Compact Session，底层复用同一条 summary/恢复机制。

实施顺序

先用测试固定“compact 只发生在采样前”，再改 summary prompt，最后处理历史 替换的细节。每一步都能独立验证。

01

写失败测试：compact 不能抢占当前 emit

覆盖 exit、有效 bash、成功 narrate 三类。 期望它们先按 bash-first 生命周期完成；compact 只在下一次采样前发生。

02

实现 pre-step compact 门禁

onUsage 只保存 usage，不再返回 stopShouldSummarize。在每次调用模型前检查 shouldAutoCompact：用户 turn 第一采样前，以及 continuation 采样前。

03

规范 summary 输出

Summary prompt 要求单个 narrate handoff。v1 不做 runtime 包装；compact 指令作为最后一条 user message，前缀复用正常会话的 bash-first system prompt。

04

保留最近用户消息

参考 Codex 的 replacement history，summary 之外固定保留最近 3 条真实用户消息。 这样最新需求、纠正和偏好不会只依赖 summary 模型是否写全。

05

加手动 Compact Session 命令

命令面板暴露主动 compact 入口，busy 时拒绝，空闲时调用和自动 compact 相同的总结路径。

已收敛的决议

目前这轮实现没有阻塞性 open question。以下是已经拍板的 v1 边界。

history

保留多少最近用户消息

v1 固定保留最近 3 条真实 user messages；不保留 runtime result、旧 summary，也不把 compact re-entry 的运行时提示算作真实用户消息。

reentry

continuation 如何重建 prompt

新用户 turn 前如果已超阈值，先 compact，再写入当前用户请求。mid-turn compact 只发生在 result/re-prompt 已持久化后的下一次采样前，然后用现有 re-entry prompt 继续。

validation

是否校验单个 narrate

当前结论是 v1 先不做复杂校验。可以保留一个简单测试和后续入口：如果模型不遵守 heredoc 格式，再考虑轻量检测或重试。
