Protocol Plan · Draft

把 Lenos 收回到单一 bash protocol

用 runtime 注入的 narrate bash builtin 承载人类可读输出， 让 SQLite 继续做唯一持久状态，去掉 :md 带来的双 mode 混合问题。

Top-level shape: bash only Narration: command result metadata SQLite remains SSOT No fsnotify state

Decision

:md 解决了 markdown 渲染，但它让一个 assistant emit 同时拥有 bash 和 markdown 两个顶层协议。GPT-5.5 已经复现了混合输出： 前半段是 bash，后半段在同一个 response 里写 :md。

  • 长期方向：顶层只允许 bash。
  • 沟通方式：narrate <<'EOF'。
  • 自然语言 detector 保留，但改写成 narrate heredoc。
  • bash 成功且 delivery 成功时，narration 渲染后结束 agent loop。
  • bash 失败或 delivery 失败时，渲染 narration，同时给模型 runtime observation 继续修复。
  • model history 不重复接收 narration result body。

一个顶层协议

Runtime 不再判断“这个 response 是 bash 还是 markdown”。每个 assistant emit 都是 bash；通信只是 bash 执行过程中的受控副作用。

一个持久 writer

子进程不直接写 SQLite。它只写临时 IPC 目录；Lenos parent 读完后在同一套 message service 中落库。

不重复喂模型

Assistant history 保留它自己 emit 的完整 heredoc。Command result 上的 narration body 只给 TUI/路由使用，不进入 FormatResults()。

01问题定义

当前 :md 是一个 in-band escape hatch。它很容易进入 TUI，也方便存库， 但它破坏了 bash-first 的纯度：模型会把“执行调查”和“输出结论”放进同一个 response。首行是 bash 时，后续 :md 会被 bash 当作命令执行。 

# model emitted one response
rg -n "responses_websockets|mount_sse_once" codex-rs
:md
结论是：Responses 有 SSE，也有 feature-flag WebSocket。
这个失败不是“小模型能力不足”。它来自协议形状本身：两个顶层 mode 让模型有机会混合。

02目标协议

目标：assistant emit 永远是 bash。要输出给人，就执行 narrate。narrate 是 Lenos 注入的 bash function， 不是普通外部工具，也不是第二种顶层 response type。切换后不再支持 :md 语法。

普通执行

# inspect the transport path
rg -n "responses_websockets|mount_sse_once" codex-rs

最终沟通

narrate <<'EOF'
模型 Responses backend 主要走 HTTPS/SSE；
代码里也有 feature-flag 控制的 WebSocket transport。
EOF

narrate 不中断当前 bash。它只记录 event 并 return 0。 整个 bash 执行结束后，Lenos 检查 IPC dir；如果有 valid narration event， result 附带 narration metadata，TUI 渲染。只有 bash exit code 为 0 且 addressed delivery 成功时，agent loop 才停止。

如果 bash 最终失败，narration 仍然渲染给人，但 loop 继续；TUI 先展示失败的 command result，再展示同一个 result 附带的 narration body。模型下一轮只看到 bash failure 和一条不含 body 的 runtime observation。
保留当前 natural language detector，但改变它的 rewrite 目标：当 runtime 确定 assistant emit 是自然语言时，直接改写成 narrate heredoc 后走同一条 bash 执行路径。 
# model ignored prompt and emitted plain prose
我已经检查完，结论是 X。

# runtime rewrites before execution
narrate <<'LENOS_NARRATE_EOF'
我已经检查完，结论是 X。
LENOS_NARRATE_EOF

03IPC 方案

推荐 IPC 是临时目录下的 per-event directory，而不是 watch SQLite、直接写 SQLite、 stdout sentinel 或 JSONL。每次 narrate 调用创建一个事件目录， 里面放 raw body 和可选 to 文件。

方案 判断 原因
Lenos watch SQLite 不采用 SQLite 文件变化不是语义事件；WAL、checkpoint、事务边界都不适合做 UI/loop 信号。
narrate 直接写 SQLite 不采用 子进程要知道 schema、migration 和锁；还会和 parent message writer 竞争。
stdout marker 不采用 污染命令输出，用户命令可能撞 marker；结果渲染和模型 observation 更难保持干净。
临时 IPC dir + raw event dirs 采用 子进程只写 raw files；parent 读事件并写 SQLite。SQLite 仍是唯一持久状态。 
LENOS_NARRATE_DIR=/tmp/lenos-narrate-abc123

narrate() {
  # parse --to
  LENOS_NARRATE_SEQ=$((LENOS_NARRATE_SEQ + 1))
  prefix="$(printf '%06d' "$LENOS_NARRATE_SEQ")"
  event_dir="$(mktemp -d "$LENOS_NARRATE_DIR/$prefix.XXXXXX")"
  # optional: printf '%s' "$to" > "$event_dir/to"
  cat > "$event_dir/body"
  return 0
}

Per-event directory 避免了 shell 里做 JSON escaping、base64 portability、 以及并发 append 的问题。Shell function 只依赖 mktemp、 printf 和 cat。Parent 按事件目录名前缀排序读取； 目录 mtime 和路径名只做异常兜底。 当前阶段 sandbox write scope 允许写 /tmp 即可。

04Runtime Flow

1. Prepare

先做分类和必要 rewrite；每次 exec 前创建 IPC dir，设置 env，并把 narrate function prepend 到 bash。

2. Execute

真实 bash 解析 heredoc、管道、注释和 quoting；runtime 不重新实现 shell parser。

3. Capture

narrate 写 body/to 后返回成功；后续 bash 语句按正常 shell 语义继续执行。

4. Persist

bash 完成后，parent 读取 IPC event，把 narration 附加到当前 command result。

5. Render

TUI 先渲染 command result，再从 CommandContent.Narrations 渲染 markdown；loop 是否停止由 bash/delivery 状态决定。

type CommandNarration struct {
    Body string `json:"body,omitempty"`
    To   string `json:"to,omitempty"`
    DeliveryExitCode *int `json:"delivery_exit_code,omitempty"`
    DeliveryOutput string `json:"delivery_output,omitempty"`
}

type CommandContent struct {
    Command string `json:"command"`
    Output string `json:"output"`
    ExitCode *int `json:"exit_code,omitempty"`
    Pending bool `json:"pending"`
    Observation string `json:"observation,omitempty"`
    Narrations []CommandNarration `json:"narrations,omitempty"`
}

多个 narrate event 按事件目录序号保留。MVP 可以把 CommandContent.Narrations 实现为 slice；TUI 依次渲染，--to delivery 也逐条执行。

bash result delivery result runtime behavior
exit 0 no --to, or send ok Persist result + narration, render markdown, stop agent loop.
exit 0 ttal send --to failed Persist delivery failure, render body locally, append runtime observation without body, continue loop.
non-zero any Render failed command result first, then narration body; append bash failure observation without repeating body, continue loop.

05History 和 Token 规则

关键点：不要把“模型自己的 assistant emit”和“runtime result metadata”混为一谈。 模型应该看到自己 emit 的完整 bash，包括 narrate heredoc body； 但 result observation 不应该再重复 narration body。

Assistant history

narrate <<'EOF'
我已经检查完，结论是 X。
EOF

保留完整 emit。这是模型自己说过的话，不能替换成 [omitted]。

Result replay

<result>
narrate delivered
</result>

FormatResults() 排除 CommandNarration.Body，避免重复 token。

Result replay 只描述 narration 状态，不包含 body。例如： narration rendered to user; body omitted from result replay。 如果 bash 或 delivery 失败，observation 仍包含失败原因，但 narration body 仍只存在于 assistant emit 和 CommandContent.Narrations。

06narrate --to

narrate --to mira 是 addressed narration 的唯一语法。Shell function 只写 IPC，不直接执行 ttal send。Lenos parent 负责路由 并把 delivery 结果写回 CommandNarration。 

narrate --to mira <<'EOF'
请 review 这个 protocol 设计。
EOF
  • 成功：bash 也成功时，TUI 显示 sent 状态，agent loop 结束。
  • 失败：TUI 显示 delivery failure，并给模型一条不含 body 的 runtime observation，loop 继续。
  • body 不进 model result replay；assistant emit 已经包含了它。

07Cutover Plan

Step 1

删除 :md 协议面

移除 classifier 的 :md 分支、prompt 中的 :md 说明、TUI 的 :md 特殊渲染路径。

Step 2

加入 narrate runtime builtin

每次 bash 执行注入 shell function 和 IPC dir。Function 只记录 body/to 并 return 0。

Step 3

CommandContent 增加 Narration 字段

bash 完成后读取 IPC event，写入 result metadata。TUI 从 result part 渲染 markdown；FormatResults() 排除 body。

Step 4

自然语言 detector 改为 narrate rewrite

确定是 prose 的 assistant emit 直接包成 narrate heredoc 执行，不再走 markdown protocol。

这是一次性切换，不做双协议窗口。旧 session 里的 :md 只作为历史文本存在； 新 loop 不再把 :md 当协议语法。

08TDD Coverage

  • narrate <<EOF 写 IPC，bash 成功后 result 附带 CommandNarration.Body，loop 结束。
  • 带 narration 的 bash 失败时，TUI 先显示失败 result 再显示 narration body，loop 继续。
  • narrate --to agent delivery 失败时，写入 delivery failure，runtime observation 不含 body，loop 继续。
  • 纯自然语言 emit 被 rewrite 成 narrate heredoc，并走同一条 result/narration 路径。
  • narrate --to agent 由 parent 调用 ttal send --to，delivery 状态落库。
  • 同一 bash emit 中多次 narrate 会创建多个事件目录，TUI 按顺序渲染。
  • Sandbox runner 当前阶段允许写 /tmp，普通 workspace 权限不被扩大到其他路径。
  • FormatResults() 不包含 narration body，但 assistant history 保留完整 emit。
  • TUI 把 narration markdown 渲染为 command result 的附属内容，不创建新 message type。
  • :md 不再有 classifier/TUI special case；新 prompt 不再提 :md。

09实现细节

  • 多次 narrate：每次调用用 shell counter + mktemp -d 创建事件目录，parent 按序号排序。
  • IPC payload：事件目录内写 raw body 和可选 raw to，Go 侧读入 CommandNarration。
  • 自然语言 rewrite 的 heredoc delimiter：使用 LENOS_NARRATE_EOF_<8hex>，若 body 中撞上则重新生成。
  • Sandbox write scope：当前阶段允许写 /tmp，后续再收紧到单次 IPC dir。
  • Unix socket：不是 MVP。只有需要 live narration 或更强跨进程一致性时再考虑。
建议先实现最小 v1：narrate 只记录 IPC event 并返回成功；bash 完成后，Lenos 如果读到 valid event 就写入 result narration metadata。只有 bash 成功且 delivery 成功时才停止 agent loop；否则给模型 runtime observation 继续修复。 v1 只支持 stdin heredoc 和 --to；:md 语法同步移除。
