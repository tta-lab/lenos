# Runtime Recovery

Recovery messages are result observations generated by the runtime. They
correct model shape errors without adding a second output protocol.

## Empty Emit

An empty response gets a short runtime prompt asking for bash, a comment,
`narrate`, or bare `exit`.

## Invalid Bash

If `bash -n` rejects the emit, the runtime sends the syntax error back and
suggests an explicit `narrate <<'EOF'` heredoc when the likely mistake is
reader-facing prose.

## Tool-Call Wrappers

If the model emits XML, JSON, or bracket-shaped tool-call markup, the runtime
deletes that assistant row and sends a high-salience alert. Replaying the bad
wrapper would teach the next turn to copy it.

## Command Not Found

If bash reports the first missing command, the runtime prepends an alert before
the normal result envelope. This covers both real missing binaries and
chat-shaped lowercase prose that was ambiguous enough to execute.

## Timeout

A timeout is stored as a command result with exit code 124 and a re-prompt
suggesting bash-native `timeout`.

## Narration Delivery Failure

If `narrate --to <agent>` fails during `ttal send`, the result stores the
delivery exit code and output in `CommandNarration`. The next model observation
mentions delivery failure but omits the narration body.

## Narration Continue

If `narrate --continue` is used, successful bash does not stop the loop. The
next model observation mentions that continue was requested and still omits
the narration body.
